# Как запустить редактор

Нужны [uv](https://docs.astral.sh/uv/) (Python 3.12 поставит сам) и Node.js.

```bash
uv sync && (cd web && npm install && npm run build)   # один раз
uv run python -m studio.server                        # http://127.0.0.1:8765
```

Дальше в шапке: «＋ Импортировать из bot-engine / создать…» – список всех `launches/*/funnel*.yaml`.
Граф сохраняется в `data/funnels/<запуск>__<воронка>.json` (папка в `.gitignore`), прошлое
сохранение – в `data/funnels/.history/`. Другая папка данных – `--data <путь>` или `STUDIO_DATA`.
Путь к репозиторию ботов – `BOT_REPO_PATH` (по умолчанию `demo/botrepo`).

Режим разработки (горячая перезагрузка холста):

```bash
uv run python -m studio.server --dev        # только API на 8765
cd web && npm run dev                        # http://localhost:5173, /api и /files проксируются на 8765
```

Адрес `#f=<запуск>__<воронка>` открывает воронку сразу, `#focus=<key>` – на нужном шаге.

## Проверки

```bash
uv run pytest                  # круговой тест, сервер, «воссоздать с нуля», версии, симулятор, сверка копии движка, движок (на Postgres), импорт из Miro
cd web && npm test             # vitest: операции, проверки, полосы, «воссоздать» четырёх образцов
cd web && npm run build        # tsc + сборка в web/dist
cd web && npm run e2e          # настоящий браузер (Chrome): действия мышью и клавиатурой
cd web && npm run e2e:bots     # раздел «Боты» на фальшивом Bot API (сам поднимает его и сервер Студии)
```

Что держит холст быстрым:
- узлы живут в локальном состоянии холста, перетаскивание не пересобирает воронку до отпускания;
- неизменённая карточка получает тот же объект данных и не перерисовывается;
- после первого показа рисуются только видимые карточки;
- на карточке – уменьшенная копия картинки (`/files/...?w=640`, кэш в `data/thumbs`).

`e2e` ждёт запущенный сервер (лучше с отдельной папкой данных:
`uv run python -m studio.server --data <временная папка>`) и установленный Chrome
(путь меняется переменной `BROWSER`).

## Экран

- **Шапка**: выбор воронки и импорт, ветка (фишки времени пересчитываются в часы ветки), TG / MAX
  для превью карточек, ↶ ↷, слой заметок, «⚠ Проверка N», «Сохранить», «Выгрузить yaml».
- **Палитра**: 8 основных типов (сообщение с картинкой, текст, кружок, запрос телефона, запрос
  почты, видео и GIF, звонок, SMS) + вопрос опроса + заметка и правка. Клик – карточка в центр
  экрана, перетаскивание – в точку холста (и в полосу под ней).
- **Холст**: перетаскивание (координаты – в `layout`), рамка – Shift + протянуть, Delete,
  Ctrl+C / Ctrl+V (копия – новый id и key `…_copy`), двойной клик – курсор в текст панели.
  Точки выхода: снизу «по времени» (с Alt – параллельная стрелка, пунктир), у кнопки-действия
  своя, у запроса телефона и почты – «дал / не дал / уже известен», у вопроса опроса – «следующий
  вопрос». Конец стрелки можно перетащить на другой шаг. Ctrl+Z / Ctrl+Shift+Z, Ctrl+S.
- **Панель шага**: тип (с предупреждением, что пропадёт); «когда отправить» – конструктор без
  свободного текста (по стрелке / в точное время ЧЧ:ММ + день + «если время прошло» / от эфира
  или повтора, своё для каждой ветки, «можно ночью») с готовой фразой как на доске; условия из
  §4.5 с доп. полями (залы, окно, префикс ссылки); текст на вкладках TG | MAX (как в TG / свой /
  скрыть), визуальный редактор с плашками плейсхолдеров и режим HTML, автозамены `[ИМЯ]` /
  `ИМЯ,` / `ОСНОВНОЕ ВРЕМЯ` / `ВРЕМЯ ПОВТОРА` / длинное тире, счётчик 1024 / 4096; кнопки с
  целью из списка (канал, ВИП, эфир, подарок, своя ссылка, действие, ответ опроса);
  кнопка-действие; медиа с загрузкой; настройки телефона / почты / опроса / звонка / SMS;
  переходы и переход в другую воронку; заметки к карточке; «расширенные» (key, закреп, варианты –
  просмотр).
- **Полосы**: для импортированной воронки раскладываются сами по смыслу – «Регистрация»,
  «Канал» (дожимы «не в канале»), «ВИП», «День N» по `day_offset`, «Опрос», «Вне цепочки»
  (шаги, которые шлёт внешний модуль). Создать / переименовать / удалить – в панели воронки;
  карточка принадлежит полосе, куда её положили. Верх полосы хранится в `layout.positions`.
- **Заметки и правки**: стикеры (свободные или на карточке), правки со сквозным номером,
  действием, автором и статусом «открыта → сделана → принята / отклонена»; «сделана» ставится
  сама, когда карточку правки изменили. В строке состояния – «Правки: N (сделано, открыто…)».
  В yaml не попадают никогда (проверяется тестами).

## Операции редактора (`web/src/model/ops.ts`)

Все правки – чистые функции `(граф, аргументы) → граф`; интерфейс вызывает только их, история
undo/redo – это прошлые графы. Нарушение инварианта – `OpError` с русским текстом.

`addStep`, `removeStep` (есть входящие стрелки, вход ветки/когорты или шаг из yaml – не удаляется,
а становится надгробием `jump` с перенаправлением), `setType` (+ `typeChangeLosses`), `setKey`
(id не меняется), `setMisc`, `setStartStep`, `setText` / `setButtons` / `setClaim` по платформам
(`set` / `inherit` / `hide`), `setClaimSettings`, `setVariants`, `setMedia`, `setSchedule`
(правила движка для `*_by_branch`), `setConditions`, `setContact`, `setEmail`, `setSurvey`,
`setCall`, `setSms`, `setPin`, `addEdge` (вид стрелки должен подходить шагу; одна стрелка каждого
вида, кроме параллельных; параллельные – без дублей; задержка «по времени» и перехода в воронку
общая), `setEdgeDelay`, `setEdgeKind`, `retargetEdge`, `setEdgeFunnel`, `removeEdge`,
`setPositions`, `addLane` / `updateLane` / `removeLane` / `assignLane` / `setLanes`, `addNote` /
`updateNote` / `removeNote`, `addRevision` / `setRevisionStatus` (статусы – только по порядку),
`duplicateSteps`, `fixDashes`, `setFunnelMeta`, `setBranchRouter`, `setEntryVariants`.

**Главный тест** – «воссоздать с нуля» (`web/src/model/recreate.ts`): по импортированному графу
строится последовательность операций, которая из пустого графа собирает ту же воронку с новыми
id. vitest сверяет результат с импортом по смыслу (без раскладки) на четырёх демо-воронках;
`tests/test_recreate_via_ops.py` прогоняет то же на всех воронках демо-репозитория и сверяет yaml
воссозданного графа с оригиналом через `load_funnel` движка.

## Проверки на панели «⚠ Проверка» (`web/src/model/validate.ts`)

Номера – из приложения А исследования. Клик по строке – шаг на холсте.

| № | Что | Уровень |
|---|---|---|
| 1 | плейсхолдер, которого нет в движке (`render.py`) | ошибка |
| 2 | тег, который Telegram не примет; незакрытый / перепутанный тег | ошибка |
| 3 | подпись к медиа > 1024 (уйдёт двумя сообщениями); текст > 4096 TG / 4000 MAX | предупр. / ошибка |
| 4 | длинное тире – кнопка «исправить все» | предупреждение |
| 13 | текст «телефон уже известен» без «всегда слать текст» | ошибка |
| 30 | ВИП-кнопка ведёт на подарок | ошибка |
| 39 | стрелка в шаг, которого нет | ошибка |
| 40 | повтор технического имени | ошибка |
| 41 | параллельная стрелка у шага с условием (при пропуске теряется) | ошибка |
| 42 | в шаг не ведёт ни одна стрелка и это не вход | предупреждение |
| 45 | кнопка без цели или без подписи (ответы опроса – норма) | предупр. / ошибка |
| 55 | два шага цепочки на одно время (второй выпадет), по каждой ветке | ошибка |

## Сервер (`studio/server`)

| Адрес | Что |
|---|---|
| `GET /api/funnels` | сохранённые воронки |
| `GET /api/sources` | все `launches/*/funnel*.yaml` в bot-engine (с пометкой «уже в Студии») |
| `POST /api/import` | yaml из bot-engine → граф (`overwrite` – переимпорт) |
| `POST /api/funnels` | новая пустая воронка |
| `GET` / `PUT /api/funnels/{имя}` | граф; при сохранении – проверка pydantic, ошибки по-русски с key и id шага |
| `POST /api/export` | граф → yaml → `load_funnel`; для импортированной – отличия от оригинала по шагам и полям |
| `POST /api/media` | файл → `data/media/<sha256>.<ext>`; картинка без EXIF, ≤ 1920 px, ≤ 1 МБ; видео как есть; в шаг пишется `./static/<файл>` |
| `GET /files/<запуск>/static/<путь>` | медиа для превью: загруженное в Студию, иначе `static` запуска в bot-engine |

Загруженные файлы в yaml ссылаются как `./static/<sha256>.<ext>`: при выгрузке их нужно положить
в `launches/<запуск>/static/` (автоматическая передача – вместе с публикацией, этапы 2–3).
