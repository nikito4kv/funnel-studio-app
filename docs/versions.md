# Версии и публикация

У воронки один **черновик** (его пишет «Сохранить», как раньше) и **неизменяемые версии** v1, v2, …
Всё лежит в `data/studio.db` (SQLite, стандартный `sqlite3`):

| Таблица | Что |
|---|---|
| `drafts` | черновик: граф, от какой версии идёт (`base_version`), время, число сохранений, откуда перенесён |
| `versions` | версия: номер, статус «опубликована» / «архив», автор (пока «я»), комментарий, время (UTC), родитель, граф, папка выгрузки, сводка |

Менять у версии можно только статус и только вперёд (опубликована → архив) – остальное запрещают
триггеры базы, удалить версию нельзя. Опубликованная у воронки всегда одна (уникальный индекс).
При старте сервер сам переносит все `data/funnels/*.json`, которых ещё нет в базе, в черновики;
старые файлы не удаляются, а `data/funnels/<имя>.json` (+ `.history/`) и дальше пишется при каждом
сохранении – как копия для глаз и страховка. Источник правды – база.

**Опубликовать** = черновик → новая версия «опубликована», прежняя → «архив» (с этапа 3 – ещё и в
движок, если он подключён: см. «Публикация из Студии в движок»). Публикация **bot-engine не трогает**: фиксирует версию и кладёт выгрузку в
`data/exports/<запуск>/<воронка>/v<N>/` – `funnel.yaml`, `check.json` (круговая проверка движком,
сводка «было / стало», предупреждения) и `static/` с загруженными в Студию файлами из yaml.
**Откатить к vN** = черновик становится копией vN (слой заметок черновика остаётся – он к версии
не относится); опубликовать откат – отдельной кнопкой.

**Дифф по смыслу** (`studio/versions/diff.py`) – по неизменяемому id шага, не по key: шаги добавлены /
удалены / сняты надгробием / переименованы (key другой, id тот же) / изменены по полям (тип, текст
и кнопки TG и MAX с «как в TG / свой / скрыт», медиа, время, условия, настройки телефона, почты,
опроса, звонка, SMS, закреп…); стрелки добавлены / удалены / перенаправлены / другая задержка;
настройки воронки (ветки и их окна, вход, залы, подпись кружка в MAX…). Раскладка, полосы и заметки
не сравниваются. Каждая строка – по-русски словами карточки:
«Шаг «s_remind1»: время «параллельно · через 3 мин» → «параллельно · через 5 мин» (стрелка из «s_welcome»)»,
«Шаг «s_remind2» удалён», «Добавлена стрелка s_welcome → z_reminder (параллельно · через 1 ч)».

Дифф считается на сервере – одни правила для всех. Фразы времени и условий –
`studio/versions/phrases.py`, порт `web/src/phrases.ts`; чтобы они не разошлись, обе стороны
сверяются с одним эталоном `web/src/versions/__fixtures__/phrases_golden.json` на четырёх образцах
воронок (vitest – TS, pytest – Python; пересобрать: `uv run python -m studio.versions.golden`).

**Блокеры публикации** (кнопка недоступна, пока не исправлено):
- ошибки панели «Проверка» (считает браузер, сервер получает их число и тоже отказывает);
- шаг, который был в опубликованной версии, исчез без надгробия – у людей могут стоять таймеры на
  него (исследование §6.1–6.2). Прямо в диалоге: «куда вести людей» → «Вернуть надгробием»;
- черновик не проходит модель или выгрузка не проходит круговую проверку движком;
- изменений нет.

**Предупреждения** (показываются, не блокируют) – что будет с людьми внутри воронки: переименование
(в нынешнем движке таймеры привязаны к имени), новое время шага или задержка стрелки (уже поставленные
таймеры не пересчитаются), другой первый шаг.

## Интерфейс

- **Шапка**: «Черновик · изменено N» / «Опубликована v3» / «Черновик · не опубликована» (клик –
  история), галочка «Изменения», «Опубликовать…». N пересчитывается сам через 0,4 с после правки –
  и только когда поменялся смысл (перетаскивание карточек дифф не дёргает).
- **Диалог публикации**: сохраняет несохранённое, сверху красным – блокеры, дальше «что будет с людьми»,
  проверка движком, «было / стало» по группам; комментарий; «Опубликовать vN». Клик по строке –
  карточка на холсте.
- **Панель «🕘 История»** (третья вкладка справа): черновик и «что изменено», версии (номер, статус,
  время по МСК, автор, комментарий), «Сравнить с черновиком» (холст подсвечивает изменения
  относительно этой версии), «Сравнить с предыдущей» (список под версией), «Откатить сюда».
- **«Изменения» на холсте**: добавленные карточки – зелёная рамка, изменённые (и переименованные,
  и снятые) – жёлтая, удалённые – бледная красная тень на старом месте, новые и изменённые стрелки
  подсвечены; сверху легенда с числами. Карточки не пересобираются – к узлу добавляется только класс.

## API

| Адрес | Что |
|---|---|
| `GET /api/funnels/{имя}/versions` | версии (новые сверху) + состояние черновика |
| `GET /api/funnels/{имя}/versions/{N}` | граф версии N |
| `GET /api/funnels/{имя}/diff?a=published&b=draft` | дифф любых двух: `draft` / `published` / номер |
| `POST /api/funnels/{имя}/diff` | дифф несохранённого графа редактора против опубликованной или версии N |
| `POST /api/funnels/{имя}/publish/check` | что опубликуется: дифф, блокеры, предупреждения, выгрузка |
| `POST /api/funnels/{имя}/publish` | опубликовать (`comment`, `number` – защита от гонки); 409 – блокеры |
| `POST /api/funnels/{имя}/rollback` | черновик := копия версии N |

## Проверки

```bash
uv run pytest tests/test_versions.py      # хранилище, миграция, неизменяемость, публикация, архив,
                                          # откат, блокеры, дифф на демо-воронках, эталон фраз
cd web && npm test                        # + эталон фраз TS, «вернуть надгробием»
cd web && npm run e2e:versions            # браузер: публикация → правки → дифф → блокер → надгробие → v2 → откат
```

`e2e:versions` ждёт сервер на 8771 (`uv run python -m studio.server --port 8771
--data <временная папка>`) или адрес первым аргументом / в `STUDIO_URL`.
