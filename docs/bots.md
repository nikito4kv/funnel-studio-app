# Боты

Раздел «Боты» – всё про самих ботов, а не про воронки: какой бот в каком запуске, имя, описания,
аватар и команды меню. Вход – «Ещё → Боты» (на пустом экране – кнопка «Боты»), адрес `#bots`
(`#bots=<id бота>` – сразу на бота).

**Что умеет.**
- **Список.** Слева – добавленные боты (аватар, имя, @username, где работают: «в Студии: запуск
  studio-test», «в bot-engine: запуск webinar – Spreadsheet Automation Workshop»). Ниже свёрнуто «Без токена в Студии» –
  боты запусков bot-engine (`launches/*/launch.yaml`, `bot.tg.username`) и движка Студии, чьего токена здесь
  нет: видно, какой бот в каком запуске, «Добавить» – вставить его токен. Ещё ниже – общие MAX-боты
  (только показ: какие запуски через них работают; имя берётся из ссылки `max.ru/<бот>?start=` в
  `launch.yaml`, аватар и имя MAX-бота меняются в кабинете MAX).
- **Добавить бота** – вставить токен из @BotFather (пошагово: @BotFather → /mybots → бот → API
  Token). Студия спрашивает `getMe` и показывает карточку. Неверный токен – «Это не похоже на токен…»
  или «Telegram не знает такой токен – возможно, его отозвали…». Тот же бот ещё раз – обновляется
  токен (после отзыва).
- **Профиль** читается из Telegram при каждом открытии (источник правды – Telegram, не наш кэш):
  имя (до 64), описание (до 512 – «что видит человек в пустом чате до /start»), короткое описание (до
  120 – «в профиле бота и в превью ссылки»), аватар, команды меню («/команда – описание»). У каждого
  поля счётчик, «Сохранить» – только это поле, «Вернуть как было». Справа – «как увидит человек»:
  пустой чат с описанием и кнопкой «Старт» и карточка профиля с коротким описанием.
- **Аватар** – картинка грузится обычной загрузкой медиа Студии (без EXIF, ≤ 1920 px), превью
  «сейчас → станет» в кружке; сервер режет квадрат по центру (≤ 1024 px) и отдаёт Telegram JPEG –
  другой формат он не принимает. Меньше 160×160 – не даём.
- **Боевой бот** (есть в `launch.yaml` bot-engine или просто без `test` в имени) – любая правка сначала
  показывает «было → стало» (было – свежее из Telegram) и «Бот работает у людей (запуск …)», меняется
  только после «Изменить». Это держит сервер, а не только интерфейс: без `confirm: true` – 409, и в
  Telegram ничего не отправляется.
- **Чего нельзя через API** – пошаговые подсказки @BotFather с кнопками «скопировать»: картинка в
  пустом чате (`/setdescriptionpic` + «подготовить и скачать 640×360»), встроенный режим (`/setinline`),
  домен и мини-приложение (`/setdomain`, `/newapp`), приватность в группах (`/setprivacy`) – с тем, как
  сейчас (по флагам `getMe`).
- **Бот ↔ запуск.** «Где работает» у бота ведёт к воронкам: воронки Студии, отправленные в его запуск
  движка (или выбранные для него), и импортированные воронки запуска bot-engine – клик открывает
  воронку. В диалоге «Запустить в боте» под выбором бота – аватар, имя и «профиль бота»; в шапке у
  «Работает в боте @…» – аватар бота.

**Безопасность: только методы профиля.** В раздел добавляют и боевые боты, которых прямо сейчас поллит
bot-engine. Один токен – один поллер: `getUpdates`, `setWebhook`, `deleteWebhook`, `logOut`, `close`
уронили бы боевого бота, а отправка сообщения ушла бы людям. Клиент (`studio/bots/telegram.py`) знает
белый список и на всё остальное бросает `ForbiddenMethod` до сети:

| | методы |
|---|---|
| чтение (при открытии) | `getMe`, `getMyName`, `getMyDescription`, `getMyShortDescription`, `getMyCommands`, `getUserProfilePhotos` + `getFile` и скачивание файла аватара |
| запись (по кнопке) | `setMyName`, `setMyDescription`, `setMyShortDescription`, `setMyProfilePhoto`, `setMyCommands` |
| никогда | всё остальное, в том числе `getUpdates`, `setWebhook`, `deleteWebhook`, `logOut`, `close`, `send*`, `removeMyProfilePhoto` |

Настройки читаются и пишутся для всех языков сразу (без `language_code`); если у бота заданы отдельные
имя или описание для какого-то языка, Студия их не показывает и не трогает.

**Где токены.** `STUDIO_DATA/bots.json`, права 600: про бота (id, @username, имя, последние 4 символа
токена) – открыто, сам токен – зашифрован (Fernet, пакет `cryptography`). Ключ – не в папке данных:
`STUDIO_SECRET_KEY` (случайная строка от 24 символов; на сервере – в `.env` стека), а без неё – файл
`STUDIO_SECRET_KEY_FILE` (по умолчанию `~/.funnel-studio/studio_secret.key`, создаётся сам) – для
запуска на ПК. Почему шифрование, а не просто файл 600: папку `data/` копируют целиком (перенос на
сервер, бэкап, разбор ошибок), а без ключа из `.env` зашифрованный файл бесполезен. От того, у
кого есть и `.env`, и `data/`, не защищает ничто, кроме отдельного хранилища секретов (например, менеджера секретов). Сменился ключ – раздел так и пишет: «токены надо добавить заново».

Токен после сохранения в браузер не возвращается (в ответах – только `last4`) и в журнал не пишется:
у логгеров `httpx` / `httpcore` / `studio.*` фильтр вырезает `bot<токен>` из адресов, httpx не пишет
запросы на INFO, ошибки сети – только имя исключения. Тело «добавить бота» сервер разбирает сам –
ошибка схемы FastAPI вернула бы токен эхом. Боты движка (`bots.secret_ref = env:ИМЯ`) показываются в
списке, их токен Студия не читает и ссылку не меняет.

Аватары кэшируются на 10 минут в `data/bot_avatars/` (не секрет). Адрес Bot API – `STUDIO_TG_API`
(по умолчанию `https://api.telegram.org`; тесты и e2e – фальшивый), прокси – `STUDIO_TG_PROXY`.

| Адрес | Что |
|---|---|
| `GET /api/bots` | свои боты (без токенов) + где работают; боты без токена; общие MAX-боты; состояние ключа |
| `GET /api/bots/index` | «@username → id, имя» – для аватара в шапке и в диалоге запуска |
| `POST /api/bots` `{token}` | добавить (getMe) |
| `DELETE /api/bots/{id}` | забыть токен (в Telegram ничего не меняется) |
| `GET /api/bots/{id}` | профиль из Telegram, флаги `getMe`, где работает, пределы |
| `GET /api/bots/{id}/avatar` | аватар через сервер (адрес файла с токеном в браузер не уходит) |
| `PUT /api/bots/{id}/profile/<поле>` `{value, confirm}` | `name`, `description`, `short_description`, `commands`, `photo`; у боевого без `confirm` – 409 с `was` / `now` |
| `GET /api/bots-tools/description-pic?media=` | картинка 640×360 для `/setdescriptionpic` |

**Привязать бота к запуску движка Студии из интерфейса – пока нет.** Движок берёт токен из
своего окружения (`secret_ref = env:ИМЯ`), а токены раздела лежат зашифрованными у сервера Студии –
чтобы движок их читал, ему нужен ключ и новая схема ссылки (`studio:<id>`). Главное же – завести
боевого бота в движок Студии значит начать его поллить вторым процессом рядом с bot-engine, и боевой бот
упадёт. Планируется встраивание Студии в bot-engine: боты там – боты `launch.yaml`, которые уже
поллит `launch_engine`; «воронка ↔ запуск» станет флажком запуска, а не заведением бота. До тех пор
тестовые боты заводятся как раньше: `runtime tenant add … --bot-env`.
