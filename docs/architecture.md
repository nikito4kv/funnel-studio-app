# Устройство, проверки модели и решения

## Устройство

```
studio/

  engine_ref/reg_window.py  чистая часть reg_window движка (окна часов регистрации)
  engine_ref/drift.py    совпадает ли копия с bot-engine по полям моделей (/api/health, публикация)
  model/funnel.py        модель Студии (pydantic v2): Funnel, Step, Edge, Lane, Note, Layout
  convert/               yaml ↔ граф (mapping.py – одна таблица на оба направления)
  server/                FastAPI: app.py, storage.py, roundtrip.py, media.py, errors.py, versions.py (API версий)
  versions/              этап 2A: store.py (SQLite), diff.py, phrases.py, publish.py, golden.py
  ids.py                 детерминированные id шагов и стрелок

  canvas/                холст: узлы, стрелки, раскладка (elkjs + полосы)
```

Прочие команды этапа 0:

```bash
uv run python -m studio.report            # отчёт: шаги, стрелки по видам, «мешок»
uv run python -m studio.cli schema        # пересобрать schema/funnel.schema.json
uv run python -m studio.cli graph <funnel.yaml> -o graph.json   # yaml → граф (JSON)
uv run python -m studio.cli yaml graph.json -o funnel.yaml      # граф → yaml
uv run python -m studio.cli fixtures      # образцы графов для тестов web/
uv run python scripts/vendor_engine.py --ref origin/main   # обновить копию модели движка
uv run python scripts/vendor_sim.py origin/main            # и хелперы времени симулятора
uv run python -m studio.engine_ref.drift  # совпадает ли копия с bot-engine (BOT_REPO_PATH) – код 1, если нет
```

Копию движка брать из боевой ветки bot-engine (`--ref`), а не из рабочего дерева: оно может стоять на
чужой ветке с незакоммиченными правками. Для сверки то же самое – чистая выгрузка ветки:
`git -C <bot-engine> archive origin/main common launches | tar -x -C <папка>`,
рядом файл `.commit` с коммитом, и `BOT_REPO_PATH=<папка>` (скрипты читают коммит из `.commit`).

**Если копия отстала от bot-engine** (бывало, когда в bot-engine у шага появлялись `skip_if_registered_msk` и
`min_delay_seconds`, «Запустить в боте…» падал с HTTP 500): Студия больше не падает. Сверка
выгрузки с исходным yaml – справочная: не прочитался оригинал – в диалоге публикации и выгрузки
понятная строка «Студия не смогла сверить воронку с bot-engine: копия движка в Студии старее bot-engine
(новые поля: …)», запуск в боте это не блокирует (бот Студии работает по графу, а не по yaml).
`/api/health` показывает `engine_copy_matches_repo_bot` и список новых полей. Любая непредвиденная
ошибка сервера приходит текстом `message`, а не голым «HTTP 500».

## Как проверяется, что модель ничего не теряет

Оракул – сам движок: `load_funnel` из `bot-engine/common/launch_engine/funnel/loader.py`, скопированный
в `studio/engine_ref/` без изменений (зависит только от pydantic и pyyaml, заглушки не понадобились;
версия pydantic зафиксирована как в движке, `<2.10`). Для каждого `launches/*/funnel*.yaml`:

1. `load_funnel(оригинал).model_dump() == load_funnel(yaml после круга).model_dump()` – бот видит
   воронку после круга ровно так же;
2. идемпотентность: импорт yaml, полученного после круга, даёт тот же граф с теми же id шагов и
   стрелок, а повторный экспорт – тот же текст;
3. заметки, правки, заголовки карточек в yaml не попадают;
4. для воронок с `extends` – компактная выгрузка тоже читается движком так же;
5. JSON графа проходит JSON Schema и читается обратно без потерь;
6. каждое поле `FunnelStep` движка имеет место в модели (`tests/test_mapping.py`) – новое поле в
   движке не потеряется молча, а уронит тест.

## Решения по модели

**Граф, а не мешок полей.** Шаг движка – плоские ~85 полей, где перемешаны контент, связи, время и
гейты. В Студии шаг (`Step`) разложен на группы: `content` (по платформам), `media`, `schedule`,
`conditions`, `contact`, `email`, `survey`, `call`, `sms`, `claim`, `pin`. Все связи вынесены в
отдельные объекты `Edge`.

**id и key.** У шага неизменяемый `id` (UUID) и читаемый `key` – как в yaml. Пока источник правды –
yaml, `id = uuid5(пространство Студии, "step:<запуск>:<id воронки>:<key>")`: повторный импорт даёт
те же id, и привязанные к ним заметки и раскладка не теряются. Все ссылки внутри графа (стрелки,
входы веток, `entry_variants`) – по `id`. Переименование `key` ничего не ломает. Ссылка на шаг,
которого нет, хранится в `unresolved` (в текущих воронках таких 0) – экспорт её сохранит, предполёт
сможет показать.

**Стрелки (`Edge`).** Вид: `done`, `contact`, `skip`, `skip_if_phone_known`, `email`,
`skip_if_email_known`, `callback`, `survey_next`, `jump`, `also_fire`, `chain_to_funnel`. У
`chain_to_funnel` цель – имя воронки (`to_funnel`) и флаг «печатает…» (`typing_before`), у остальных –
шаг (`to_step`). Порядок стрелок сохраняется (важно для `also_fire`).

**Где живёт время.**
- *Относительная задержка* («через N после предыдущего / после события») – на стрелке,
  `Edge.delay_seconds`: `on_done_after_seconds`, `on_contact_after_seconds`,
  `on_skip_after_seconds` (таймаут ожидания контакта/почты; `None` = не задан, как в движке),
  `on_email_after_seconds`, `on_skip_if_*_known_after_seconds`, значения `also_fire`.
- *Абсолютное время и время от эфира* – у шага, `Step.schedule`: `absolute_time_msk`, `day_offset`,
  `day_offset_by_branch`, `webinar_offset_minutes`, `webinar_offset_by_branch`, `anchor`,
  `skip_if_past`, `dnd_exempt`, `after_start_seconds`. Это свойство шага, потому что в движке оно
  перебивает задержку любой входящей стрелки. `schedule.mode` сразу говорит, какой это случай:
  `chain` (по стрелке), `clock` (по часам), `webinar` (от эфира/повтора).
- У движка одна задержка на `on_done` и `chain_to_funnel`. В Студии она лежит на обеих стрелках;
  экспорт откажется выгружать шаг, если на них разные значения.
- Проверки движка (`*_by_branch` без базового значения) повторены в модели – ошибка ловится в
  редакторе, а не на старте бота.

**Платформы.** `content.tg` – текст, кнопки, подпись claim-кнопки для Telegram. `content.max` – те
же три поля для MAX с семантикой движка: `None` = «как в TG», пустое (`""` / `[]`) = «в MAX этого
нет». Поля MAX поэтому `Optional`, и круговой тест проверяет, что эти состояния не смешиваются.
Варианты по когортам (`content.variants`) – с условием `when` и своими формулировками.

**Настройки воронки.** `branch_router` (ветки, окна, время эфира, `repeat_offset_minutes`; вход
ветки – ссылка на шаг по id), `entry_variants`, `webinar_room`, `max_video_note_caption`,
`air_email_profile`. `webinar_room` и `max_video_note_caption` хранятся как настройки и **не**
разворачиваются в шаги при импорте – их разворачивает движок при загрузке, так же как раньше.

**`extends`.** При импорте разворачивается так же, как в движке (ключи ребёнка целиком перебивают
родительские), – в редакторе видна полная воронка. В `source` запоминается путь к родителю и свои
ключи ребёнка. По умолчанию экспорт полный (самодостаточный yaml); `compact=True` / `--compact`
выгружает прежнюю форму «extends + свои ключи» – годится, пока унаследованные разделы не правили.
Настоящее наследование (версия-родитель → версии-дети) – задача этапа 2.

**Заметки и правки** (`notes`) – отдельный тип объекта: заметка-стикер (свободная, на карточке или
на полосе) и правка со сквозным номером, действием и статусом. Экспорт их не читает вовсе, поэтому
записка не может уйти в бот. Туда же не уходят `lanes`, `layout`, `role`, `title` и `source`.

**Роль шага** (`role`, `role_day`) – перечисление из раздела 8.2 исследования, на этапе 0 не
заполняется.

**Экспорт в yaml** пишет только значения, отличные от умолчаний движка (умолчания берутся из самой
модели движка), в порядке полей `FunnelStep`. Поэтому явные `parse_mode: HTML` из исходников
исчезают – смысл тот же. Строки вида `13:00` и даты всегда в кавычках (без них YAML прочитал бы
780), кириллица и эмодзи – как есть, многострочный текст – блоком `|`.

**«Мешок» `Step.advanced`** – только для полей, которым в модели нет законного места: мёртвый
`parse_mode`, не равный HTML, задержка без цели, `typing_before_chain` без перехода в воронку, и
любое новое поле движка, про которое модель ещё не знает. На всех демо-воронках мешок **пуст**.
