# Симулятор

Вкладка **«▶ Симулятор»** в правой панели отвечает на вопрос «что и когда получит человек и что у
него выпадет». Задаёте момент регистрации (МСК), TG или MAX и «человека» – жмёте «▶ Прогнать».

- **Лента по дням** («День регистрации», «День 1»… с эфирами и повторами ветки в этот день): время,
  значок, шаг, первая строка текста и что случилось – ✉ отправлено, ⏳ ушло с опозданием 120 с,
  🌙 сдвинуто ночным режимом, ⛔ пропущено условием (каким), ✖ выпало – время прошло, ✂ параллельная
  ветка потеряна / цепочку сняло нажатие кнопки, ↻ таймер перезаписан вторым путём, ⌛ ждём действия
  человека, 👤 что сделал человек. Фильтр «всё / сообщения / потери и сдвиги». Клик – шаг на холсте.
- **Сводка**: ветка и эфир, сколько ушло, сколько выпало и почему (список кликабелен), настройки
  запуска, которые повлияли (ночной режим, канал не подключён, `tg_skip_steps`).
- **На холсте** после прогона: над карточкой – «уйдёт 13:05» (или «25.09 13:05»), у выпавших –
  красная пунктирная рамка, у пропущенных условием – серая пунктирная. «Очистить» снимает отметки.
  Фишки времени переключаются на ветку, в которую попал человек.
- **«Все ветки»** – прогон по 09:00, 12:30, 17:30, 23:30 и по последней минуте каждого окна веток
  (поздняя регистрация теряет больше всех); для фикс-даты – за 3 дня и в день эфира. Таблица «ветка,
  уходит, выпадает» и список «шаги, которые выпадают – при какой регистрации». Клик по строке –
  подробная лента этого момента.
- **«Человек»**: был на эфире дня N, оплатил ВИП / купил курс / вступил в канал / кликнул ссылку /
  написал менеджеру (и через сколько минут), телефон и почта уже известны, опрос пройден, есть
  лидмагнит; действия – даёт контакт, жмёт кнопки-действия, отвечает на опрос, присылает почту (через
  сколько секунд). По умолчанию «типовой»: контакт дал через 15 с, кнопки жмёт через 20 с, в канал не
  вступил, ВИП не оплатил, на эфирах не был.
- **«✈ Тест в TG»** – отправить воронку себе через ТЕСТОВОГО бота в сжатом времени (пауза 1,5 с):
  переменные сервера `STUDIO_TEST_TG_TOKEN`, `STUDIO_TEST_TG_CHAT`, прокси `STUDIO_TG_PROXY`. Без них
  кнопка неактивна с подсказкой. Порядок сообщений – из симулятора, над каждым – «когда и какой шаг»;
  кнопки-ссылки – ссылки, кнопки-действия неактивны, картинки – файлом из `static` запуска, кружки и
  видео – строчкой. Боевые токены bot-engine Студия не читает.

## Как считает (`studio/sim`)

Симулятор работает над тем, что увидит бот: граф выгружается в yaml и читается `load_funnel`
движка. Время шагов и ночной режим считают **скопированные файлы движка** `branch.py` и `dnd.py`
(`studio/sim/engine/`, `scripts/vendor_sim.py`, коммит в шапке; правка только в импортах – `datetime`
берётся из часов симуляции). Логика планирования `runner.py` / `max_runner.py` перенесена в
`studio/sim/simulator.py` метод в метод, со ссылками на строки оригинала. Вместо APScheduler – своя
очередь с той же семантикой (id таймера по шагу, второй путь перезаписывает первый, отмена по id).

Правила, которые симулятор воспроизводит (и проверяют тесты):
- время от эфира / по часам перебивает задержку стрелки; прошло – шаг выпадает и сразу идёт дальше
  («если время прошло – пропустить»), либо уходит через 120 с («всё равно отправить»);
- два шага цепочки на одно время – второй выпадает (правило 55);
- у шага, пропущенного условием, `on_done` идёт, а параллельные стрелки теряются (правило 41);
- параллельная стрелка без своего времени ночной режим не соблюдает;
- кнопка-действие снимает таймер следующего шага, если нет «кнопка не обрывает цепочку»; потерей
  считается, только если ничего из снятой цепочки человек так и не получил (кнопка «Начать», ведущая
  в тот же шаг, – не потеря);
- вопрос опроса ждёт ответа; режим «править сообщение» на шаге после опроса останавливает цепочку;
- повтор шага в окне 90 с не шлётся; переход в другую воронку – конец прогона (в MAX переходов нет);
- в TG канал без `chat_id` – шаги «в канале / не в канале» молча пропускаются; в MAX решает
  `max_gate_fallback`; при известном телефоне / почте TG-движок не запускает параллельные стрелки
  шага, MAX – запускает.

Горизонт – 14 суток и 2000 событий. Не моделируются: сетевые сбои, повторный /start, когорты
(`entry_variants`), game-модули, письма каскада.

## API

| Адрес | Что |
|---|---|
| `POST /api/funnels/{имя}/simulate` | `registered_at` («2026-09-24T10:00», МСК), `platform`, `persona`, `dnd` (null – как в запуске), `graph` (необязательно – несохранённая воронка с холста) → лента, дни, сводка, отметки |
| `POST /api/funnels/{имя}/simulate/matrix` | `date`, `platform`, `persona` → строки по моментам регистрации + выпадающие шаги |
| `GET /api/testrun`, `POST /api/funnels/{имя}/testrun` | настроен ли тестовый бот; отправка |

## Проверки

```bash
uv run pytest tests/test_simulator.py   # правила движка на синтетических воронках, три демо-воронки, матрица веток, API, тест-прогон с подменой HTTP
cd web && npm test                      # + лента симулятора (format.test.ts)
cd web && npm run e2e:sim               # браузер: прогон, клик по событию → карточка, рамки, «Все ветки», «Очистить»
```

На демо-воронках проверяются, например: автовебинар на 3 дня – регистрация до 12:00 → эфир 13:00
сегодня, 12–17 → 18:00 сегодня, после 17:00 → 13:00 завтра; кружок 9:00 и меню 9:05 первого дня
уходят с опозданием (`skip_if_past: false`, `min_delay_seconds`); вечерняя ветка не теряет утро
следующих дней; купивший ВИП получает все дни; воронка «эфир завтра в 13:00» – повтор 16:01 → 16:32
кружок → 18:00 + SMS, был на эфире – повтор пропущен, а день 2 приходит; звонок и кружок на одну
минуту – второй выпадает (правило 55).
