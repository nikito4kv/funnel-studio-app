# Импорт из Miro

Постановщик рисует воронку в Miro, разработчик вставляет в Студию ссылку на фрейм – Студия собирает
воронку сама (сообщения, картинки, кнопки, стрелки, время, условия), подсвечивает, в чём не уверена, и
при изменении доски обновляет черновик через «было / стало», не теряя ручных правок. Правила для
постановщика – [docs/miro_rules.md](miro_rules.md) (и подсказка в диалоге импорта). Правила разбора
русскоязычные: стикеры вроде «через 3 минуты если не перешёл в канал» читаются по-русски.

## Как пользоваться

- **«Ещё → Импорт из Miro…»** (или в окне «Открыть воронку» – «Из Miro») – ссылка на фрейм (в Miro:
  правый клик по фрейму → «Copy link to object»), запуск и имя воронки → «Импортировать». Идёт
  снятие фрейма, раскладка, скачивание картинок (прогресс «N из M»); итог – «собрано N сообщений,
  K мест проверить» и список этих мест. Новая воронка сразу сохраняется черновиком.
- **Подсветка**: у карточки с сомнениями – метка «проверить N», в панели шага – блок «Собрано из
  Miro» со ссылкой «открыть в Miro» (на сам элемент доски) и сомнениями; в панели «Проверка» –
  правило №90 «импорт из Miro: проверить» со ссылкой на элемент. «Проверено» убирает замечание
  (Ctrl+Z – вернуть), повторный импорт его не возвращает. «Сделано по правилам» (ВИП не шлём
  купившим, `{channel.link}` вместо ссылки и т.п.) – для сведения, в «Проверку» не попадает.
- **Повторный импорт той же доски** – «Ещё → Обновить из Miro…» (ссылка подставлена): вместо
  перезаписи – «было / стало» по смыслу (тот же дифф, что у версий) и «Применить». Шаги
  сопоставляются по элементу Miro: новые на доске – добавляются (с местом на холсте рядом с
  предыдущим), исчезнувшие – убираются (key убранного шага новому не отдаётся: таймеры людей в
  движке привязаны к имени; если на шаге стоят люди, публикация попросит надгробие), шаги,
  созданные в Студии руками, остаются. У каждого поля, которое даёт доска (тип, текст, кнопки,
  картинка, условия, настройки телефона / почты / опроса, стрелки и их задержки), – три версии:
  «как было на доске в прошлый раз» (`Step.miro.board`, `Funnel.miro.edges_base`), «как в
  черновике», «как на доске сейчас». Не трогали в Студии – берётся доска; правили в Студии, а доска
  не менялась – остаётся правка; поменяли и там, и там – берётся доска и появляется сомнение
  «поменяли и на доске, и в Студии, в Студии было: …». Полей, которых на доске нет (бот, key,
  раскладка, заметки, ролик кружка, текст MAX, расширенные), импорт не касается.

## Как Студия читает доску (`studio/miro/`)

| Файл | Что |
|---|---|
| `client.py` | Miro REST v2, только GET: фрейм по ссылке (`moveToWidget` / `focusWidget`), элементы фрейма и коннекторы страницами, картинки оригиналами (`format=original&redirect=false`), повтор при 429/5xx. Токен – `MIRO_TOKEN`, адрес – `MIRO_API_BASE` |
| `dialect.py` | **первый шаг импорта** – диалект доски (A «Запуск», B «Белые скруглённые», C «По дням», D «Короткие воронки»): по самому частому цвету длинных текстов и цвету элементов времени; таблица диалекта – цвета и формы сообщений, кнопок, плашек и стикеров времени (данные, не условия под доску) |
| `board.py` | роли элементов по таблице диалекта: сообщение (в A – зелёный #adf0c7, в C – голубой #c6dcff и белый скруглённый, в B/D – белый), кружок – круг, звонок – ромб «+ автозвонок»; кнопка – белая (или короткая плашка цвета сообщения) под сообщением; подпись-тайминг – плашка времени («за 30 мин до эфира», «в 9:00 по МСК»); картинка и альбом – над сообщением; стикер; полоса-заголовок раздела; прочее – не в бот. Стрелки, идущие сквозь стикеры и подписи (конец дня → «2 день» → «в 9:00» → кружок), склеиваются в один путь; путь в пустоту и путь без начала запоминаются |
| `rows.py` | фрейм-«расписание» (C): полосы дней по стикерам «N день» и пустым щелям, колонки слева направо, подпись – к колонке (над стрелкой – к цели, под колонкой – к ней), время: от эфира / от повтора / по часам / «в 9:50 ИЛИ в 15:50» по веткам, стикеры веток «в 13:05 / в 18:05», «повтор» и «если не был», правило веток, окна регистрации и «поменять таймер» из записок |
| `stickers.py` | разбор стикеров: `RuleParser` (по умолчанию) и `ClaudeParser` (ниже) |
| `html.py` | разметка доски → HTML Telegram: абзацы и `<br>` – переводы строк, `strong` → `b`, `em` → `i`, ссылки, `span` и цвета – прочь, пробелы на краях тегов – наружу |
| `build.py` | доска → граф: вход – стрелка кнопки «СТАРТ» (первая колонка – описание бота, не шаг); порядок и развилки – по стрелкам; тип шага по содержимому; стикеры → задержки, условия, «уже известен»; правила переноса (ниже); у каждого шага `miro` – элемент доски, все его элементы и сомнения; id шага – `uuid5(доска, элемент)`, поэтому повторный импорт попадает в ту же карточку |
| `merge.py` | повторный импорт (см. выше) |
| `compare.py`, `__main__.py` | сверка с эталоном и командная строка |
| `fake.py` | фальшивый Miro по снимку – для тестов и e2e |

Правила переноса – те, по которым воронки раньше переносили вручную:
кружок – сценарий в «что говорит спикер» (в MAX подпись скрыта), ролик загружает разработчик;
«ОТПРАВИТЬ КОНТАКТ» – запрос телефона (от кнопки – «дал номер», от сообщения – «не дал», стрелка
«СТАРТ» мимо него – «номер уже известен»); «введите e-mail» – запрос почты (почта известна – шаг
пропускается, не прислал за 10 минут – дальше); кнопки-ответы без ссылок – вопрос опроса
(«несколько» или «✅ Готово» – несколько ответов; последний вопрос перед почтой – без правки
сообщения); кнопка без ссылки со стрелкой – кнопка-действие; одна стрелка из сообщения – «дальше
по времени», несколько – все параллельные (каждая отсчитывает своё время от сообщения), у шага с
условием параллельная перевешивается на ближайший шаг выше без условия; ссылка-приглашение канала
и страница ВИП – `{channel.link}` / `{vip_link}` (сверяется с `launch.yaml` запуска); ВИП-сообщения
– «не оплатил ВИП»; «Имя,» – `{Имя}`; длинное тире – «–»; строки-заглушки «[ССЫЛКА НА VIP]»,
«(ссылка)» и строка с одной ссылкой, которая уже есть на кнопке, – убираются; скрытая в кнопке
вторая ссылка (копия прошлого запуска) – не берётся. Письмо после оплаты («Тема: …»), страницы
сайта и раздел доски не из «входа» (реферальная игра, «оплатили ВИП») – не переносятся.

Сомнения («проверить»): кружок без ролика; «не поняла стикер / время»; стрелка без стикера; стрелки
нет, но есть стикер со временем между сообщениями (проведена по стикеру – так на досках пропускали
«ВИП-дожим → опрос»); «если нажал» у кнопки-ссылки (движок нажатия на ссылку не отслеживает);
дожим «через 2 минуты, если остановился» посреди опроса и кнопка «вернуть в опрос» (это делает
game-модуль, в цепочку не встраиваются); вторая ссылка на канал (часто – прошлого запуска); кнопка
без ссылки и стрелки; стикер, не отнесённый ни к одному сообщению; ромб-развилка; стрелка за
фрейм; сообщение, в которое не ведёт ни одна стрелка.

## Фрейм-«расписание» (автовебинар по дням)

Кроме досок «Запуск» (зелёные сообщения и стрелки) Студия читает доски, нарисованные «по дням»:
сообщения голубые, время – жёлтые плашки под колонкой, порядок задают координаты (стрелок почти нет).
Диалект определяется первым шагом (`dialect.py`), роли элементов читаются по его таблице.

- полосы дней, колонки, подписи и ветки – `rows.py`; каждый день – своя цепочка «дальше» по времени,
  все дни армируются разом из входа (`also_fire` с нулём): сквозная цепочка теряет утро следующего
  дня у вечерней ветки; два шага на одно время разводятся на минуту;
- время шага: «за N до эфира» / «через N мин эфира» – `webinar_offset_minutes`, правее стикера
  «повтор» – `anchor: repeat` + «не был на эфире», «в 9:00 по МСК» – часы + `day_offset` дня,
  «в 9:50 ИЛИ в 15:50» – `webinar_offset_by_branch`; нет подписи – время из первой строки текста,
  нет и там – «сразу за предыдущим» и «проверить»;
- правило «через N» без слова «эфир»: после шага по часам – от него (9:00 → «через 5 минут» = 9:05);
  после шага от эфира короткая пауза (≤ 10 мин) – от него, длинная – от начала эфира;
- правило веток со стикера → `branch_router`; ромб «+ автозвонок» – шаг `call`; записки
  «ПОСТАВИТЬ ОГРАНИЧЕНИЯ … с 10:00 ПО 12:00» – окна регистрации, «ПОМЕНЯТЬ ТАЙМЕР … НА 30 МИНУТ» –
  задержка входящей стрелки;
- на фрейме несколько ботов (регистрация, мини-курс, посевы) – воронка = бот из раздела «вход /
  регистрация» (разделов нет – самый левый «СТАРТ»).

В публичной копии для этого диалекта нет снимка доски: тесты покрывают диалект «Запуск»
(`tests/fixtures/miro/workshop.json`), `rows.py` отдельными тестами не закрыт.

## Ничего не пропадает: заметки и счёт элементов

Всё, что не стало шагом, остаётся на холсте **заметкой** (`notes`, автор «Miro») на том же месте
доски, с исходным текстом и причиной «⚠ с доски Miro: …»: сообщение вне цепочки, письмо, «оплата
прошла», картинка без сообщения, стикер ни к чему не отнесённый, ромб, стрелка в пустоту (красная).
Записки разработчику у сообщения («ПО КНОПКЕ…», «ДОБАВИТЬ…», «ПРАВКА…») – заметкой на карточке и
замечанием «проверить». В итоге импорта (окно, CLI, `stats.board`) – счёт: элементов на доске / в
шагах / в настройках (дни, ветки, повтор, описание бота, подсказки времени) / заметками / пропущено
с причиной (только пустые фигуры) / «не учтено» (должно быть 0 – это проверяют тесты); то же для стрелок: стали переходами, в днях (порядок по колонкам), в подписи, в пустоту,
за фрейм.

**Раскладка** повторяет доску: карточка встаёт на место колонки (масштаб 0,32 – колонка Miro
~1150 единиц → карточка 320 px), полосы «Вход и регистрация», «День 1…5» – по полосам доски,
свободные заметки – на месте элемента. Холст открывается без авто-раскладки.

## Разбор стикеров через Claude

`ClaudeParser` включается сам, если на сервере задан `ANTHROPIC_API_KEY` (пакет `anthropic` уже в
зависимостях): правила идут первыми, в Claude уходят только стикеры, в которых правила не уверены.
Модель `claude-opus-5` (или `STUDIO_CLAUDE_MODEL`), низкое усилие, структурированный ответ по
JSON-схеме: задержка, исход стрелки (дал номер / не дал / нажал / остановился…), условие (не в
канале, не оплатил ВИП, не прошёл опрос…), «уже известен», непереносимое и **уверенность** 0–1 –
ниже 1 шаг подсвечивается. Отказ модели или ошибка сети – остаётся разбор правилами. Без ключа
импорт работает на правилах. Тесты – на фальшивом клиенте.

## API и настройка

| Адрес | Что |
|---|---|
| `GET /api/miro/status` | задан ли `MIRO_TOKEN` (и ключ Anthropic) |
| `POST /api/miro/import` | `{link, launch, name}` → `{job}`; импорт идёт в фоне |
| `GET /api/miro/jobs/{job}` | этап, картинки «N из M», итог: `name`, `created`, `stats`, `doubts`; для повторного – `diff` и `report_text` |
| `POST /api/miro/jobs/{job}/apply` | сохранить слитый граф повторного импорта в черновик |

Картинки – в медиа Студии тем же путём, что загрузка файла (без EXIF, ≤ 1920 px, ≤ 1 МБ,
`./static/<sha256>.jpg`), снимок фрейма – в `data/miro_cache/`. Имя занято воронкой не из этого
фрейма – ошибка «выберите другое имя». Токен – `MIRO_TOKEN` в окружении сервера (см. `deploy/.env.example`), в git и логи не попадает; Miro Студия только читает.

## Командная строка

```bash
MIRO_TOKEN=… uv run python -m studio.miro "<ссылка на фрейм>" --compare launches/webinar/funnel.yaml
uv run python -m studio.miro снимок.json --compare launches/webinar/funnel.yaml [--json] [--out graph.json]
```

Снимок кэшируется в `data/miro_cache/`. С `--compare` эталон (yaml) читается обычным импортом, шаги
сопоставляются по смыслу (текст, тип, картинка), метрики – доля верного от эталона.

## Проверки импорта

```bash
uv run pytest tests/test_miro.py tests/test_miro_server.py   # разбор HTML и стикеров, Claude на фальшивом
                     # клиенте, клиент Miro на фальшивом API, раскладка выдуманной доски
                     # (tests/fixtures/miro/workshop.json), выгрузка движком, повторный импорт,
                     # сервер: задание, картинки в медиа, «было / стало» → «Применить»
cd web && npx vitest run src/miro                             # правило «проверить», «Проверено», ссылка на Miro
cd web && npm run e2e:miro                                    # браузер + фальшивый Miro: импорт → холст →
                     # «Проверка» → «Проверено» → ручная правка → доска поменялась →
                     # «Обновить из Miro» → «было / стало» → «Применить»
```
